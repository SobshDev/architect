# M0 spikes

Three spikes ran before M1 to settle the riskiest integration questions. All three passed, so the plan's fallbacks are not needed.

## 1. MCP SDK v2 over stdio under Bun

`@modelcontextprotocol/server` 2.1.0 runs under Bun 1.3.14 with no shims. A test server registered one tool with zod input and output schemas, `annotations: { readOnlyHint: true }`, and a resource template, then served it with `serveStdio(createServer)`. Logs go to stderr only.

- `McpServer` and `ResourceTemplate` come from `@modelcontextprotocol/server`; `serveStdio` comes from `@modelcontextprotocol/server/stdio`.
- A handler returns `{ content: [{ type: "text", text }, { type: "resource_link", uri, name }], structuredContent }`.
- `registerResource(name, new ResourceTemplate("architect://decisions/{id}", { list }), { description, mimeType }, read)` serves `architect://` links.
- The v2 client (`@modelcontextprotocol/client`, `StdioClientTransport` from `@modelcontextprotocol/client/stdio`) connected in the legacy era by default (64 ms) and in the modern era with `{ versionNegotiation: { mode: "auto" } }` (111 ms).
- In-process tests can use `createMcpHandler(createServer)` with a `StreamableHTTPClientTransport` whose `fetch` calls the handler, or `InMemoryTransport.createLinkedPair()` for the legacy era. Close the client before the handler.
- Codex CLI 0.154.0 (`codex exec` with `-c mcp_servers.<name>.command/args`) and Claude Code 2.1.261 (`claude -p --mcp-config <file> --strict-mcp-config`) both listed and called the tool.

The v1 SDK fallback is not needed.

## 2. TypeScript and tree-sitter inside a compiled binary

TypeScript 6.0.3 (the newest release below 7.0) and web-tree-sitter 0.27.0 both work in `bun build --compile` output.

- `ts.createSourceFile` parses without a Program. `ts.resolveModuleName("./b.js", ...)` with `moduleResolution: Bundler` resolves to `b.ts` through a host backed by an in-memory file list.
- web-tree-sitter loads with `Parser.init({ wasmBinary })` and `Language.load(bytes)`, where both wasm files are imported with `with { type: "file" }` and read with `Bun.file(path).bytes()`. This embeds them in the binary.
- The compiled binary is 73 MB and starts in about 80 ms; importing TypeScript takes 15 to 26 ms. `--bytecode --format=esm` also works (104 MB).
- The Python grammar is `tree-sitter-python` 0.25.0 (MIT). Its prebuilt wasm is vendored at `src/analysis/python/grammar/tree-sitter-python.wasm`; the npm package is not a dependency because it pulls native build tooling.

## 3. Codex hook payloads

The generated JSON schemas for Codex hooks were fetched from `openai/codex` (`codex-rs/hooks/schema/generated/`) and saved in `test/fixtures/hooks/codex/schemas/`. Input schemas set `additionalProperties: false`.

| Event | Input fields beyond the common ones | Output |
|---|---|---|
| SessionStart | `source`: startup, resume, clear, compact, or fork | `hookSpecificOutput.additionalContext`, `systemMessage`, `continue` |
| UserPromptSubmit | `turn_id`, `prompt` | `decision: "block"` with `reason`, or `hookSpecificOutput.additionalContext` |
| PostToolUse | `turn_id`, `tool_name`, `tool_input`, `tool_response`, `tool_use_id` | `decision: "block"` with `reason`, `hookSpecificOutput.additionalContext` |
| Stop | `turn_id`, `last_assistant_message`, `stop_hook_active` | `decision: "block"` with `reason`, `systemMessage` |

Common input fields: `cwd`, `hook_event_name`, `model`, `permission_mode`, `session_id`, `transcript_path`. For `apply_patch`, the patch text arrives in `tool_input.command`, and changed paths come from its `*** Add File:`, `*** Update File:`, `*** Delete File:`, and `*** Move to:` lines.

Live payloads were not recorded in M0 because hooks need trust in the host. The adapters are tested against fixtures that validate against these schemas; M3 records live payloads where the hosts allow it and confirms Claude Code's hook format.
